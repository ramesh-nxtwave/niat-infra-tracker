Before pushing the Infra Tracker live, do a complete production checklist to ensure:

* Existing university data is safe
* New UI changes do not break old functionality
* Percentages/timelines work correctly
* Filters/navigation/session handling work properly
* No production data loss happens

Use this final pre-production checklist with Replit:

---

# Final Production Checklist – Infra Tracker

## 1. Database Safety Check (MOST IMPORTANT)

### Verify:

* Existing university data is still present
* Old remarks are intact
* Evidence files/images are accessible
* Timelines are preserved
* Checklist completion data is preserved
* Allocation status values are preserved

### Mandatory:

Before deployment, take:

* Full database backup
* Export all tables/data
* Backup uploaded images/files

If using:

* Supabase → export backup
* PostgreSQL → pg_dump
* Firebase → export collections
* Replit DB → export JSON backup

---

# 2. Ensure Schema Changes Are Non-Destructive

For new fields:

* Priority
* Action Items
* Timeline filters
* Image upload
* Latest remarks

Use:

* ALTER TABLE
* Optional/default values

DO NOT:

* Drop existing columns
* Recreate tables
* Reset migrations

Example safe approach:

* New columns should allow NULL/default values
* Existing universities should still work even if old records don't have new fields

# 10. Production Deployment Strategy

Recommended safest approach:

### Step 1:

Create staging/preview deployment

### Step 2:

Test with existing production data

### Step 3:

Take database backup

### Step 4:

Deploy UI changes only first

### Step 5:

Run migration scripts carefully

### Step 6:

Verify live data immediately after deployment

# Important Recommendation

Do NOT directly overwrite production first.

Best practice:

1. Clone current working app
2. Deploy upgraded version separately
3. Test with real data
4. Then switch production

This avoids accidental data loss.
